# Развёртывание бота СТО на Bothost (bothost.ru)

Bothost берёт код из Git (или zip-архива) и собирает его по `Dockerfile` из корня репозитория.
Секреты и настройки СТО задаются переменными окружения в панели, файл `.env` на хостинг не нужен.

## Что важно знать заранее
- **Тариф «Базовый»** (тот же, что для DETAIL LAB, до 5 ботов на тарифе): на бесплатном нет переменных окружения и база стирается.
- **База хранится в `/app/data/sto_bot.db`** (задано в `Dockerfile`). Эта папка переживает обновления кода и перезапуски.
- **Один токен работает только в одном месте.** Если бот запущен у тебя на компьютере, останови его
  (`pkill -f bot.py`), иначе в логах будет `Conflict: terminated by other getUpdates`.
- Токен никуда не вставляем, кроме поля **Bot Token** в форме Bothost.

## Шаги
1. **Создание бота:** https://bothost.ru/create-bot.php

   | Поле | Значение |
   |---|---|
   | Платформа | Telegram |
   | Язык | Python, версия **3.12** |
   | Bot Token | токен из @BotFather |
   | Локация | Россия (Москва); если в логах сетевые ошибки до Telegram, пересоздать с Нидерландами |
   | Git URL | `https://github.com/khadiev17timur-tech/sto_bot` (приватный, см. шаг 2) |
   | Ветка | `main` |
   | Главный файл | `bot.py` |

   **Переменные окружения:**
   ```
   ADMIN_ID=<числовой Telegram ID владельца, узнать у @userinfobot>
   STO_NAME=<название СТО>
   STO_ADDRESS=<адрес>
   STO_PHONE=<телефон, +7...>
   STO_WORKING_HOURS=ПН-ПТ 09:00-19:00, СБ 09:00-18:00, ВС 09:00-17:00
   WHATSAPP_URL=<https://wa.me/7..., или пусто, чтобы скрыть кнопку>
   TELEGRAM_URL=<https://t.me/..., или пусто>
   SCHEDULE_CHANNEL_ID=<необязательно: @канал или -100... для карточек записей>
   ```
   `BOT_TOKEN` платформа подставляет сама из поля формы. `DB_PATH` задавать не нужно.

2. **Приватный репозиторий.** Либо подключить GitHub по инструкции Bothost («Подключение приватного
   репозитория»), либо загрузить архив. Архив без секретов и базы собирается из git:
   ```bash
   cd sto_bot && git pull && git archive --format=zip -o ~/Downloads/sto_bot.zip HEAD
   ```
3. **Проверка.** В «Логах работы» должно быть `База данных инициализирована`,
   `Автогенерация расписания` и `Бот запущен`. Затем в Telegram:
   `/start` → запись на услугу → уведомление пришло владельцу → «Моя запись» → отмена → «Админ-панель» видна только `ADMIN_ID`.

## Обновление
- Из Git: «Обновить из Git» в панели. Из архива: собрать новый архив и загрузить; токен, переменные и `/app/data` сохраняются.
- Услуги, цены и часы работы меняются в `config.py` (`SERVICES`, `WORKING_HOURS`) и выкатываются обновлением.

## Если что-то не работает
| В логах | Что делать |
|---|---|
| `Conflict: terminated by other getUpdates` | бот с этим токеном запущен где-то ещё, остановить его |
| `Unauthorized` | токен неверный или отозван, вставить актуальный в настройках бота |
| `Не задан ADMIN_ID` / `ADMIN_ID должен быть числом` | проверить переменную `ADMIN_ID` (нужны цифры, не @username) |
| `TelegramNetworkError` подолгу | нет связи с Telegram из локации, пересоздать бота в Нидерландах |
| `ModuleNotFoundError` | выбрана версия Python ниже 3.11, выбрать 3.12 |
| Записи «пропали» после обновления | база писалась не в `/app/data`: проверить, что не задан свой `DB_PATH` |
