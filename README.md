# Telegram-бот для автосервиса (СТО)

Бот на **aiogram 3**, **SQLAlchemy 2.x (async)** и **SQLite** для онлайн-записи
клиентов на СТО: календарь на месяц вперёд, услуги разной длительности (в т.ч.
многочасовые — блокируют несколько слотов подряд), защищённое от гонок
бронирование, автонапоминания за 24 часа и полная админ-панель.

## Реализованный функционал

**Клиент:**
- Inline-календарь, расписание формируется на 30 дней вперёд (`SCHEDULE_DAYS_AHEAD` в `config.py`)
- Запись: дата → время (часовая сетка) → услуга → имя → телефон → марка/модель авто →
  госномер (необязательно) → комментарий (необязательно) → подтверждение
- Каждая услуга имеет свою длительность (`config.py → SERVICES`); многочасовые услуги
  (например, «Ремонт подвески» — 2 часа) автоматически блокируют нужное число
  последовательных часовых слотов
- Один клиент — только одна активная запись одновременно (гарантия на уровне БД:
  частичный уникальный индекс `ux_one_active_booking_per_user`)
- 📋 «Моя запись» — просмотр и отмена своей записи, слот освобождается сразу
- 🔧 «Услуги и цены» — ориентировочные цены по Москве (сверены по открытым источникам
  на замену масла, диагностику, тормоза, шиномонтаж, развал-схождение), с явной
  пометкой «ориентировочные» — НЕ обязательная подписка на канал не требуется (её нет вообще)
- 📞 «Связаться с нами» — звонок / WhatsApp / Telegram; кнопки WhatsApp и Telegram
  автоматически скрываются, если соответствующий URL не задан в `.env`

**Защита от двойного бронирования (важно):**
Финальное подтверждение записи не полагается на предварительные проверки в диалоге.
`services/booking_service.py` в момент подтверждения ещё раз атомарно проверяет и
захватывает нужные слоты условным `UPDATE ... WHERE is_available = 1` внутри одной
транзакции. SQLite сериализует конкурентных писателей на уровне файла (включён
`WAL`-режим и `busy_timeout=15s`, см. `database/db.py`), поэтому при одновременной
попытке двух клиентов забронировать одно и то же время выигрывает только один — это
проверено тестом с 20 параллельными запросами на один слот (19 корректно отклонены).

**Уведомления при новой записи / отмене:**
- Владельцу бота (`ADMIN_ID`) — личное сообщение с полными данными клиента
- В Telegram-канал/чат расписания (`SCHEDULE_CHANNEL_ID`, если задан) — короткая
  карточка записи. Канал используется ТОЛЬКО для информирования, никакой обязательной
  подписки для клиентов нет

**Администратор (доступ только по `ADMIN_ID`):**
- 📅 Расписание: просмотр на дату (кто когда записан), закрыть/открыть день,
  добавить/исключить рабочий день, добавить/удалить слот
- 📋 Записи: список записей на дату с возможностью отменить (клиент получает уведомление)
- Все действия защищены проверкой `ADMIN_ID` на уровне всего router — callback_data
  от пользователя никогда не используется для авторизации

**Напоминания (APScheduler, `AsyncIOScheduler`):**
- Автоматически планируется за `REMINDER_HOURS_BEFORE` (по умолчанию 24) часов до визита
- Если запись создана менее чем за 24 часа до визита — напоминание не создаётся
- При отмене записи (клиентом или админом) задача напоминания снимается
- При перезапуске бота активные напоминания восстанавливаются из таблицы `reminders`
  без дублирования (проверено тестом на симулированный рестарт)

## Установка и запуск

> Развёртывание 24/7 на Bothost: см. [BOTHOST.md](BOTHOST.md).

### 1. Требования
- Python 3.11+ (в этом проекте протестировано на 3.9–3.12; SQLAlchemy 2.x async
  работает на 3.9+, но целимся на актуальные версии)
- Токен бота от [@BotFather](https://t.me/BotFather)

### 2. Виртуальное окружение

```bash
cd sto_bot
python3 -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
```

### 3. Зависимости

```bash
pip install -r requirements.txt
```

### 4. Получение токена бота

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram
2. Отправьте `/newbot`, укажите имя и username бота
3. Скопируйте выданный токен вида `123456789:AAH...`

### 5. Настройка `.env`

```bash
cp .env.example .env
```

Заполните:

```env
BOT_TOKEN=...                # токен из BotFather
ADMIN_ID=...                 # ваш Telegram ID, узнать у @userinfobot
SCHEDULE_CHANNEL_ID=          # необязательно: @канал или -100... для уведомлений о записях
STO_NAME=Автосервис "Пример"
STO_ADDRESS=г. Москва, ул. Примерная, д. 1
STO_PHONE=+79999999999
STO_WORKING_HOURS=ПН-ПТ 09:00-19:00, СБ 09:00-18:00, ВС 09:00-17:00
WHATSAPP_URL=https://wa.me/79999999999
TELEGRAM_URL=https://t.me/example
```

- `ADMIN_ID` — числовой Telegram ID владельца бота (не username)
- `SCHEDULE_CHANNEL_ID` — если хотите публиковать уведомления о записях в отдельный
  чат/канал, добавьте туда бота **администратором** с правом отправки сообщений и
  укажите его `@username` или числовой ID. Если оставить пустым — публикация просто
  отключается, ошибок не будет
- `WHATSAPP_URL` / `TELEGRAM_URL` — оставьте пустыми, чтобы скрыть соответствующую
  кнопку в разделе «Связаться с нами»

### 6. Запуск

```bash
python bot.py
```

При первом запуске бот создаст файл БД SQLite (`data/sto_bot.db`) и сгенерирует
расписание на 30 дней вперёд по графику из `config.py → WORKING_HOURS`.

### 7. Проверка

1. `/start` → должно открыться главное меню с 5 кнопками
2. «🚗 Записаться на СТО» → пройти весь сценарий, включая многочасовую услугу
   (например, «Ремонт подвески») — должны заблокироваться 2 последовательных слота
3. Проверить, что администратору пришло уведомление, а в канал (если настроен)
   ушла карточка записи
4. «📋 Моя запись» → отменить → слот должен снова стать доступным
5. Зайти под `ADMIN_ID` → «⚙️ Админ-панель» — должна быть видна только администратору

## Важные примечания

- **Изменение рабочего графика.** Недельный график (`config.py → WORKING_HOURS`) —
  единственное место, откуда пересчитываются слоты для новых дат. Изменения
  применяются к датам, для которых расписание ещё не сгенерировано.
- **Изменение услуг и цен.** `config.py → SERVICES` — единственное место с перечнем
  услуг, их длительностью (в часах) и ориентировочной ценой. Изменение длительности
  услуги сразу влияет на то, сколько слотов подряд она будет занимать при новой записи.
- **Цены ориентировочные.** Указаны по открытым источникам о ценах на авторемонт в
  Москве (2026 год) и явно помечены как не привязанные к конкретному СТО — перед
  реальным использованием замените на актуальный прайс вашего автосервиса.
- **«Закрыть день» vs «Удалить рабочий день».** Технически оба действия помечают день
  закрытым (клиенты не видят слоты, новые записи запрещены), различие — в намерении:
  «Закрыть» — для временных случаев (форс-мажор), «Удалить рабочий день» — для плановых
  исключений (праздники). Существующие записи в обоих случаях не отменяются
  автоматически — администратор увидит предупреждение и должен отменить их вручную
  через «📋 Записи», если нужно.
- **Часовой пояс планировщика** — `Europe/Moscow` (см. `services/reminder_service.py`).
